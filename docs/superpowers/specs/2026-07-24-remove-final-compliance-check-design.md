# 删除末尾事实与合规校验

## 目标

删除分析生成后的末尾事实与合规校验功能。新分析不再进入 `validating`，也不会因为校验失败进入 `blocked`。页面不再显示校验进度、阻止回复红条或校验详情。

## 保留范围

- 保留 L0-L4 知识检索和已审核资料引用。
- 保留生成提示词中的事实约束，避免模型主动编造企业事实。
- 保留退款、投诉、合同等高风险场景的人工升级。
- 兼容历史记录中已经存在的 `validating`、`blocked` 和 `validationReport` 数据，但新流程不再产生这些状态或字段。

## 实现设计

### 服务端

- 分析结果生成后直接保存结果。
- `handoffRequired` 为真时进入 `handoff`，否则进入 `completed`。
- 删除 `validateSalesReply` 及生成结果上的 `validationReport`。
- 删除末尾 `validating` 进度保存。
- 保留旧状态的读取、恢复或重试兼容，避免历史数据导致页面或服务异常。

### 前端

- 分析进度由五步缩减为四步，最后一步为“正在生成销管建议”。
- 删除 `blocked` 红色提示。
- 删除“查看生成前校验结果”详情。
- 删除只服务于上述界面的样式。

### 数据与接口

- 新生成的 `SalesAnalysisResult` 不再要求 `validationReport`。
- 历史 JSON 或数据库记录中的额外字段无需迁移；运行时忽略即可。
- `validating` 和 `blocked` 状态暂时保留在兼容类型中，但主动流程不再写入。

## 测试

- 服务端测试证明即使生成回复原本会触发末尾校验，任务也会完成而不是阻止。
- 模型与规则分析测试不再断言 `validationReport`。
- 前端测试证明结果页不再渲染阻止提示和校验详情。
- 运行相关单元测试、类型检查和构建。

## 不在本次范围

- 不修改知识库导入、审核、向量检索或对象存储。
- 不删除人工升级流程。
- 不调整模型提示词中的事实约束。
