# 线上知识检索质量修复设计

日期：2026-07-24

## 背景与问题

线上实例已经启用 Qdrant，健康检查显示向量库连接正常；对象存储仍为本地文件模式，但这不会直接降低文本知识检索质量。

实际线上分析能够引用上传资料，说明“上传、解析、入库、向量检索”链路是通的。当前问题是检索质量：

- 知识库中混入了“隐藏信息、标准答案、评分标准、测试说明”等测试/元知识。
- 这些内容以已发布状态进入 Qdrant，语义上又与“怎么回复客户”高度相似，因此可能排在真实产品事实之前。
- 当前混合检索在 Qdrant 返回结果非空时，只对向量 Top 30 对应的知识条目重排。没有进入这 30 条的精确产品事实，即使关键词更匹配，也没有参与后续排序。
- 模型只能从提供给它的候选知识中选择引用，因此可能引用“推荐回复、合规评分标准”等元知识，而遗漏产品定位、价格、竞品区别和售后规则。

线上复现场景是客户询问轻茶与普通乌龙茶的区别、169 元价格以及无效果风险。分析引用了《十三、智能体应生成的推荐回复》《智能体回答合规、诚实》等元知识，而没有优先引用《一、模拟产品总设定》《1. 产品真实价值》《竞品类型二：普通乌龙茶》等直接事实。

## 目标

1. 已发布的测试/元知识不再参与运行时检索，也不再写入新的 Qdrant 索引。
2. 精确关键词命中的产品、价格、竞品、案例和售后事实不会因为未进入向量 Top 30 而完全失去候选资格。
3. 保留现有安全校验和必选知识层级行为。
4. 不修改线上知识记录的发布状态，不删除或归档用户数据。
5. 不改对象存储配置和上传流程。

## 非目标

- 不重新设计知识库管理页面。
- 不自动删除、下线或改写现有知识。
- 不扩大到图片、音视频对象存储。
- 不改模型供应商、Embedding 模型或 Qdrant 集合结构。
- 不对相邻代码做无关重构。

## 设计

### 1. 统一检索资格判断

新增 `server/knowledge/eligibility.ts`，提供单一的知识检索资格判断函数。运行时检索和向量分块共用该函数，避免“运行时过滤了，但索引仍持续写入”或两处规则漂移。

判断顺序：

1. 如果 `structuredData.retrievalEligible === false`，明确排除。
2. 对知识标题、正文和可用结构化文本做规范化。
3. 仅命中高置信度测试/元知识特征时排除，例如：
   - 隐藏信息或声明“不应输入/提供给智能体”的内容；
   - 标准答案、答案要点、预期答案；
   - “智能体应生成的推荐回复”；
   - 明确用于测试、评测、打分或判断 AI 分析是否准确的说明。
4. 其他已发布知识保持可检索，避免用过宽的关键词误伤真实合规政策、销售话术或产品说明。

该规则只影响检索资格，不改变数据库记录状态。

### 2. 运行时检索过滤

`retrieveKnowledge` 在分层、强制选择和混合排序前过滤掉不具备检索资格的条目。

- L0/L1 的必选规则保持不变，但仅在具备检索资格的条目中选择。
- L2 继续提供适用的销售策略。
- L3 继续提供产品、价格、竞品、案例和售后事实。
- 被排除的测试/元知识不会进入模型提示词，也不能成为模型返回的 `sourceIds`。

### 3. 混合候选集修正

Qdrant 仍用于提供语义相似度，但不再把向量 Top 30 当作唯一候选集。

对全部“已发布且具备检索资格”的 L2/L3 条目进行统一重排：

- 命中 Qdrant 的条目获得向量分；
- 未命中 Qdrant 的条目向量分为 0，但仍可获得关键词分和分类加权；
- 沿用现有的向量、关键词和分类加权逻辑；
- L2 仅保留总分大于 0 的策略候选，避免无关的零分策略被补足进结果；
- 按现有限额选取最终知识。

这样既保留语义召回能力，也允许“169 元”“普通乌龙茶”“无效果”等精确事实通过关键词和分类相关性进入最终候选。

### 4. 向量索引过滤

`buildKnowledgeChunks` 调用同一个资格判断函数：

- 不具备检索资格的知识返回空分块；
- 对现有组织执行全量重建索引后，这些知识对应的旧向量会从新索引中消失；
- 原数据库记录及其发布状态保持不变，管理员仍可在知识库页面查看和编辑。

### 5. 引用与安全校验

模型引用流程不做结构性改动：

- 模型仍从检索结果中返回 `sourceIds`；
- 服务端仍把 `sourceIds` 映射为引用，并执行现有事实、安全和合规校验；
- 因为测试/元知识不会出现在检索结果中，模型不能再把它们作为本次分析的依据；
- 直接产品事实进入候选后，现有“需要已审核事实引用”的校验更容易得到正确依据。

## 测试方案

### 单元测试

1. 资格判断：
   - 显式 `retrievalEligible: false` 被排除；
   - 隐藏信息、标准答案、推荐回复、评分/测试说明被排除；
   - 正常的产品合规说明、销售策略和产品事实不被误伤。
2. 分块：
   - 不具备资格的知识生成 0 个分块；
   - 正常知识继续生成原有文本分块。
3. 混合检索：
   - 构造与线上相同的轻茶对话；
   - 让测试/元知识拥有更高的模拟向量分；
   - 断言测试/元知识仍被排除；
   - 断言未进入向量 Top 结果但关键词精确匹配的产品、竞品或价格事实进入最终结果。
4. 回归：
   - 保持 Qdrant 不可用时的关键词回退；
   - 保持 L0/L1 必选知识；
   - 保持现有引用映射和安全校验测试通过。

### 验收标准

- 目标测试套件通过。
- 完整测试和类型检查没有新增失败。
- 重建线上索引后，Qdrant 健康检查正常。
- 用线上复现对话重新分析时：
  - 引用中不再出现隐藏信息、标准答案、推荐回复或评分测试说明；
  - 检索结果包含与产品定位、普通乌龙茶区别、价格或售后风险直接相关的已审核事实；
  - 分析仍能正常返回，且已有安全校验正常工作。
- 线上知识记录数量和发布状态不因本次修复改变。

## 发布步骤

1. 在隔离工作树中实现并运行目标测试。
2. 运行完整测试、类型检查和构建检查。
3. 提交并推送独立修复分支。
4. 部署 API 服务。
5. 对线上组织执行一次全量知识索引重建，使旧的测试/元知识向量从新索引移除。
6. 检查 API、PostgreSQL、Embedding 和 Qdrant 健康状态。
7. 使用线上复现对话验证最终引用来源。

## 回滚

- 回滚应用版本即可恢复旧的运行时检索逻辑。
- Qdrant 索引切换沿用现有别名/重建机制；需要时可切回上一索引。
- 本次不改变知识记录状态，因此不需要恢复数据库业务数据。
